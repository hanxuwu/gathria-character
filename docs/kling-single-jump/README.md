# 单次跳跃与跑跳衔接

此前侧视的 Jump 虽然设置为不循环，但片段内部包含两次跳起。现在把基础 Jump 选成一次完整的蓄力、腾空、落地与恢复，并让落地后的动作延续起跳前的移动意图。

## 打开与操作

运行 `npm run dev`，打开：

- 男版：`/workbench.html?character=male&mode=paired`
- 女版：`/workbench.html?character=female&mode=paired`
- 键盘移动试验：相同地址将 `mode=paired` 改成 `mode=side-view`。

双视角衣橱的新会话默认使用 **单次跳跃**。选择侧视，点击 **跑步**，再点击 **跳一次**；也可以把焦点移出输入控件后按空格。人物会在选定步态处起跳，完成落地后接回跑步。待机时起跳则返回待机，走路时起跳则接回走路。

腾空中选择待机／走路／跑步，会更新落地后的目标；不会中断腾空。长按空格或连续点击不会排队再跳一次。暂停、逐帧和拖动帧位仍可检查单独姿势。两个视角使用各自原生帧序和时钟，不强行拉成相同周期。

**原片对照**保留原始完整动作，其中侧视仍是连续两跳。旧版双视角工程按原片模式打开；明确切换后保存，才会保存单跳模式。

## 素材与播放

| 视角 | 男版 Jump     | 女版 Jump     | 时长与循环                           |
| ---- | ------------- | ------------- | ------------------------------------ |
| 侧视 | 原生帧 63–90  | 原生帧 58–85  | 28 帧，24 FPS，约 1.167 秒，不循环   |
| 原版 | 原生帧 83–121 | 原生帧 83–121 | 原有 39 帧，24 FPS，1.625 秒，不循环 |

人物图集、脸、头发、衣料、锚点、尺寸和每帧时长保持原样。这里只改变 Jump 的取帧区间以及动作之间的进入／退出位置。[选帧说明](selection.md)和[原素材诊断](selection.json)记录了源视频、帧号、SHA 与关节阶段。

播放器、双视角衣橱和侧视舞台共用[动作控制器](../../src/core/gameplay-motion.ts)与[素材绑定配置](../../src/core/gameplay-motion-profiles.json)。动作切换保留时间余量，落地后从选定的跑步／走路相位接入，避免总是从第一帧重启。

## 导出与兼容

- **当前动作 GIF**：所选模式的单独动作，Jump 为一次播放。GIF 的百分之一秒计时采用累计舍入；28 帧约为 1.17 秒，CharacterPack 保留精确 24 FPS。
- **跑步 → 跳跃 → 跑步 GIF**：通过同一动作控制器生成完整衔接，非循环；左右方向均可导出。
- **CharacterPack**：保持现有格式与原图集，附带单跳片段及动作切换配置。独立播放器读取配置后同样能单跳并接回移动。只按动作数组播放的第三方播放器仍会得到一次 Jump，但需要自行实现动作切换。
- **双视角工程**：单跳模式使用外层 V2，保存模式和两个视角的帧位；原片模式继续使用原来的 V1，嵌入的原始换装工程不变。
- **当前视角换装工程**：保留原有服装／发型文件格式，不保存新动作模式。要携带动作模式请保存双视角工程或 CharacterPack。独立侧视工具的模式选择保存在当前浏览器偏好中。

## 视觉边界

单跳和完整落地可以验证，但现有视频未提供所有方向与动作之间的过渡画面。侧视起跳的头部俯仰、手臂摆位，以及落地返回待机时的手臂放下仍有姿势差异。原片中的模糊、边缘色溢和既有衣料问题仍存在。

当前跑步每周期使用一个经过检查的起跳接点，因此输入可能等待接近一个周期，最长约 0.75 秒；这保证了选定接点，不代表即时起跳。要同时提高响应速度并消除接点差异，需要更多经过审阅的起跳姿势或专门的过渡素材。

实际导出与功能、视觉检查分别记录在[验收记录](verification.md)。
