## 原速时间轴

所有人物原帧按 24 fps 播放，整段预览约 8.583 秒。

| 预览时间       | 内容                   | 实际来源                                                |
| -------------- | ---------------------- | ------------------------------------------------------- |
| 0–2.25 秒      | 走路，3 个完整双步循环 | 上轮男版 / 女版 CharacterPack 的 walk，各 18 帧循环     |
| 2.25–5.25 秒   | 跑步，4 个完整双步循环 | 上轮两包的 run，各 18 帧循环                            |
| 5.25–7.333 秒  | 跑步刹车后连续跳两次   | 男版 2360、女版 2394，均为原视频 `[200,250)` 连续 50 帧 |
| 7.333–8.083 秒 | 最后一个落地姿势停留   | 审阅停留 18 帧，明确标注；不是新增原始动作帧            |
| 8.083–8.583 秒 | 重播分隔卡             | 审阅界面；区分整段重播和动作自身循环                    |

源帧编号从 0 开始，结束帧不包含。第二次起跳约在 233–234，落地约 244–245，保留至 249 的落地缓冲，省略后续长时间半蹲。没有把第一次跳跃重复两遍，也没有时间拉伸、补帧、变形、淡化过渡或逐帧稳头。

复用上轮每个源视频的固定等比配准与透明化规则。男版源帧 242 有一小块真实裤腰轮廓与主体分离，已人工核对，明确保留原图区域 `[846,640,858,649]`；没有放宽全局碎片删除阈值，也没有重画该轮廓。其他已导出的重叠帧逐像素验证一致。

## 仍能看到的问题

- 走路、跑步与跳跃来自不同视频，切换时脸部角度、四肢体积和姿势仍有变化。
- 两跳之间是原视频真实运动；第二次落地停在浅蹲，没有补上并不存在的自然站立恢复。
- 源视频跳跃中的模糊、后颈少量绿幕溢色仍保留。GIF 的 256 色会进一步简化颜色，MP4 更适合连续播放检查。
- 本轮是原地动作预览，不包含游戏世界位移，也没有把两跳重新封装为正式动作。

## 本轮检查

[validation.json](validation.json) 记录原包 SHA-256、100 个新提取帧的来源/透明边界、逐帧时间轴，以及 3 个 GIF 和 1 个 MP4 的校验结果。GIF 检查全部帧可解码、循环标记及约 8.58 秒总时长；MP4 检查完整解码、206 帧与精确 24 fps。原包字节未变。未重跑上轮单元/播放器测试，历史通过数量不算作本次新结果。

[浏览器检查](browser-validation.json) 实际加载了新增 GIF、点击重播，并在 Chromium 中从头播放完整 8.583 秒 MP4 至结束，无视频或页面错误。[页面截图](browser-preview.png)。
