# Capture retention

Use `final-male`, `final-honey-garden`, `final-harbor-sailor-refined`, `final-rose-picnic-refined`, `final-ivory-celebration-refined` and `final-sage-pinafore-refined` for final delivery. Their indexes passed and their nine CharacterPack ZIPs are retained here. Each saved editable project was exported to temporary task storage, reopened and checked; its bytes/hash and original path are recorded without publishing another large copy of all source assets.

`final-female` is an incomplete first inspection run. It revealed defects that were corrected. Its native PNGs support the matched refinement comparisons, but its two superseded packs are not final delivery.

The four other female folders without the `-refined` suffix are completed intermediate captures made before the last donor-ink refinement. Their PNGs and historical validation indexes remain, but the superseded CharacterPack archives are not retained in Git. `retainedInRepository: false` records that retention decision; it is not a new test result.

The final refined runs reuse only the three matched before-hair PNGs from each earlier capture. Their download records explicitly say `origin: reused matched actual app export` and point to the earlier PNG. Source, registration, selected clothing and original hairstyle hashes were checked before this reuse. All final after PNGs, CharacterPacks, project reopens and standalone playback cases were captured again with the final selected hair bank.

Catalog input inventories can include hashes of unused styles that were subsequently refined. Validate the selected appearance hash in each `reopened` record and the selected garment hashes, rather than treating an unused catalog entry as part of the exported look. The final aggregate verification pins the nine selected looks to the current assets.
