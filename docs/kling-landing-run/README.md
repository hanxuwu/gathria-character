# 落地后继续跑步

这一轮针对“跳下来之后先停一下再跑”的接点。之前所有跳跃都播完回到站立的尾段，才接回跑步；原视角因此多等待 9 帧（375 毫秒）。侧视的最后一帧已经开始再次向上回弹，接入的跑步步态也不够匹配。

现在将**跑步中的落地出口**与**原地跳完站稳**分开处理。完整腾空、首次落地和下蹲缓冲仍保留；没有加速动作，也没有改变人物或服装的图像。

| 视角     | 继续跑步时的处理                                        | 完整原地 Jump         |
| -------- | ------------------------------------------------------- | --------------------- |
| 原版男女 | 落地恢复到原生帧 112 后接跑步 55，省去 375ms 的站立尾段 | 仍为 83–121，共 39 帧 |
| 侧视男版 | 原生帧 89 后接跑步 55，避开额外回弹与大跨步接点         | 仍为 63–90，共 28 帧  |
| 侧视女版 | 原生帧 84 后接跑步 47，避开额外回弹与大跨步接点         | 仍为 58–85，共 28 帧  |

侧视只少 1 帧（约 42ms），主要改善的是接点附近的姿势。首次触地到恢复跑步仍包含约 458ms 的落地缓冲和恢复，不能理解为全部是可删掉的停顿。

## 如何查看

运行 `npm run dev`，打开 `/workbench.html?mode=paired&character=male`（女版改为 `female`）。选择 **单次跳跃**，点击 **跑步**，再点击 **跳一次**。可以切换原版／侧视和左右朝向。独立侧视舞台及新导出的 CharacterPack 使用同一套接点。

待机时跳跃仍播完站稳，跳跃后接走路也保留完整尾段。如果在新出口已经过去之后才点击跑步，则使用后面的完整恢复出口，不倒退播放，也不硬切尚未审核的姿势。长按空格或重复点击不会自动产生第二跳。

## 素材、时钟和兼容

- 两个性别、两个视角的原生图集、脸型、比例、衣服、锚点和 24 FPS 均保持不变。
- 新导出的动作配置 ID 为 `*-single-jump-v2`，配置结构仍为版本 1。此前导出的精确 V1 配置继续按原来的完整恢复接点播放。
- 单独 Jump GIF 保留原来的全部帧；**跑步 → 跳跃 → 跑步 GIF** 才使用移动落地出口。
- 独立播放器还修正了动作切换导致 React 播放效果重建时丢失短暂时间的问题。暂停、重新定位或切到后台会重置计时基准，避免恢复时跳过动作。该问题影响实时播放，不是原有导出 GIF 中 375ms 停顿的原因。
