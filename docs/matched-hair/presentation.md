# 同款发型的对照展示规则

`scripts/build-matched-hair-review.mjs` 只读取应用实际导出的原生工程与 CharacterPack，生成审阅展示图。它不重新生成角色，也不改写来源帧、外观包、服装或导出包。

## 固定身体比例与地面基准

从每份工程内嵌的原片 CharacterPack 读取完整 idle 帧序列，以 alpha ≥ 128 的原人物可见范围确定身体高度、鞋底位置和水平中心。使用各项中位数，并挑选靠近中位数的最早稳定站姿作静态参考。

每个视角仅计算一次等比展示缩放：`460 / 原片 idle 可见身体高度`。所有走路、跑步、跳跃帧复用同一个缩放、原点和地面基准，不逐帧重新裁切、居中、贴地或放大。外观新增的透明边距仅用于坐标换算，不参与人物高度的计算。

当前原片的校准值：

| 人物 | 原版可见身高 | 侧视可见身高 | 原版展示倍率 | 侧视展示倍率 |
| --- | --- | --- | --- | --- |
| 男版 | 820 px | 480 px | 0.56098 | 0.95833 |
| 女版 | 846 px | 487 px | 0.54374 | 0.94456 |

以上是对照图的展示倍率，不是新的游戏单位或人物比例。原生 PNG 与 CharacterPack 保留自己的原始尺寸、锚点和像素。两段视频中的身体起伏及位移也仍然可见。

静态站姿采用一次固定 idle 视口，减少上方空白。动作 GIF 采用一次覆盖全部原生姿势的固定视口，为跳跃和举臂保留空间；动作内不改变视口大小。

## 发型设计对比

`*-matched-heads.png` 以“原版母版／旧侧视／新侧视”三列展示，使用旧版来源绑定外观包的稳定站姿 `headBounds` 高度缩放到 240 展示像素。头部测量固定在旧基准，不由新候选的遮挡范围决定。发型自身的包围盒不参与缩放，所以不能把短发放大成与长发一样高，或将过大的新发型自动压小来掩盖差异。

这是按既有头部定位框等尺寸展示，不声称两段不同视频的脸部是同一张图旋转得到的。表情、视角和原人物脸型差异继续保留。

困难姿势另外输出原生 2 倍最近邻局部图：男版侧视 `0 / 77 / 82`，女版侧视 `64 / 77 / 95`。每张采用同一个来源坐标裁框，并列展示“当前服装＋原头部／旧发型／新发型”，用于检查耳后头皮、鬓角、颈部与抬臂遮挡。三列均读取实际导出的 CharacterPack；不使用重新绘制的对照图，也不让衣服变化干扰头发修复判断。

## 时间与左右朝向

两种视角按各自原生 FPS、帧序和循环设置播放，不强制匹配动作相位。可以在 12 秒内找到共同周期时，双视角循环 GIF 使用该完整周期；例如 16 帧与 18 帧、均为 24 FPS 的跑步，完整共同周期为 6 秒。

无法在限定时间内闭合时，比较 GIF 是明确的非循环片段。跳跃保持非循环，短的一边结束后只在展示中保持最后一帧，另一边完成后一起停止；不会改写包内动作时长或将连续两跳伪装为一个循环。左右版本只镜像各自的展示人物区域，文字保持正常。

输出的 `presentation-provenance.json` 记录输入 SHA、校准姿势、身体／头部倍率、透明边距、固定基线，以及每段 GIF 的原生帧映射与展示时长。`presentation-integrity.json` 解码并记录本次生成的 PNG／GIF。GIF 的展示缩放使用固定等比双三次采样和统一调色板，不能替代原生透明 PNG 的像素验收。

## 使用

输入目录沿用浏览器验收的 `{male,female}/exports.json`，每行包含实际 `project`、`pack` 和 `view`。旧包基线默认为 PR #59 已提交的 `docs/dual-looks/review/`。

```sh
node scripts/build-matched-hair-review.mjs \
  --input /tmp/kling-hair-match/exports \
  --output docs/matched-hair/review
```

默认生成 26 份展示媒体：16 个 GIF、4 张头部／站姿比较图和 6 张原生 2 倍局部图。最终应用验收全部完成后，另执行以下装配命令，把 4 份独立 CharacterPack、36 个原生动作 GIF、原生 PNG 与浏览器截图按字节原样复制到审阅目录：

```sh
node scripts/assemble-matched-hair-review.mjs \
  --input /tmp/kling-hair-match/exports \
  --output docs/matched-hair/review
```

装配要求独立播放器、像素审计和保存重开报告已通过。较大的可编辑工程 ZIP 不重复入库，记录其 SHA-256 与大小；旧外观兼容输入明确标记为测试夹具，其重存结果才是浏览器实际下载。`actual-downloads.json` 记录复制的原生文件，`checks/review-integrity.json` 解码审阅目录中的全部 PNG／GIF／ZIP 并核对原生下载哈希。后续补充 production 截图后可执行 `node scripts/assemble-matched-hair-review.mjs --verify-only` 更新完整性报告。

只检查静态造型可加 `--static-only`。管线小样可用 `--characters male --actions run --before-actions run --directions right --duration-limit 1`，并将输出指定到 `/tmp`；有时长限制的小样不会被标记为完整循环或新素材验收结果。

展示规则已用上一轮实际导出验证尺寸、稳定坐标与解码流程；最终新发型的视觉结论需等待本轮真实应用导出，不能将管线小样当成新造型成果。
