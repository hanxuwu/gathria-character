# 双视角完整日常造型：验收记录

日期：2026-10-30。基于 PR #58 分支已提交的 `b2feaea`（该 PR 仍为未合并草稿），分支 `feat/dual-view-complete-looks`。本文件只统计本轮实际运行；旧文档中的测试次数不计入本轮。

## 实际界面流程

`tests/e2e/dual-view-complete-looks.spec.ts` 通过页面控件选择、下载和重新上传；交付文件不通过测试直接调用内部合成器制造。男女各两项流程，覆盖：

- 应用完整日常造型，两个原生视角分别保留自己的来源、定位、发型和表情 ID；栗棕、深棕、铜棕可选择。
- 关闭头发、关闭表情、恢复原片头部；服装保持。恢复后 PNG 与同帧仅衣服基线一致，重新应用完整造型又恢复原完整 PNG。
- 两种衣料配色、新上装／原片下装、原片上装／新下装。保存刷新重开后，每个视角的动作、方向、帧位、服装和外观均恢复，重保存 ZIP 字节一致。
- 外观侧视 ZIP 返回 503 时，先确认故障请求确实被拦截，再检查两个视角 PNG 和整份旧工程字节不变。损坏工程也不能覆盖当前工程。
- 旧 V1 无外观工程可以读取并逐字节重保存；带外观工程重开时拦截外部外观 ZIP 下载，确认使用工程内嵌素材，不额外请求这些素材。
- 原版五个动作、侧视四个动作，各自左右 GIF；原生透明 PNG、CharacterPack。侧视没有庆祝动作，保留禁用选项及不含该动作的包。
- 关闭编辑器后，四份 CharacterPack 分别在全新浏览器上下文加载：跑步帧确实推进，可以转向，重新导出的 ZIP 字节完全一致。播放器不请求衣橱、外观、侧视编辑器或骨骼编辑模块。
- 390 像素窄屏布局没有横向溢出。

本轮最终结果：

- 新增四项浏览器流程全部通过，耗时 12.4 分钟；日志 [browser-complete-looks.log](review/checks/browser-complete-looks.log)。每个人物的第二外观 ZIP 故障各实际拦截一次，两个已保存的原生工程均未被半替换。
- 另外 20 项原有相关浏览器回归通过：页面入口 7 项、统一导航 5 项、双视角衣橱／日常服装／独立导出 8 项。合计 **24 项不同浏览器用例通过**，首次失败、中断与重跑不重复计数。
- 单元测试 60 个文件、590 项通过；TypeScript、生产构建、男女两视角四项生产预览及窄屏检查通过。汇总与本轮日志见 [root-checks.json](review/checks/root-checks.json)。
- 最终实际下载为 393 个原生帧对应的四份 CharacterPack、36 个动作左右 GIF；关闭编辑器后的四次独立播放器加载、播放和字节相同重导出均通过。
- 外观资产另有 2,358 次原生渲染检查，修订裙料有 816 次混搭检查，以及逐字节重建检查。它们属于素材矩阵验证，不计为额外浏览器用例或单元测试。

## 独立像素与时间审计

`scripts/verify-dual-looks-exports.mjs` 从实际 UI 导出的原生工程、服装 ZIP、外观 ZIP 和 CharacterPack 解码，独立实现像素重组，不调用应用合成器。它检查全部 393 个原生帧，保留来源哈希、定位哈希、动作帧序、FPS、循环标记和原视频帧映射。

原版 704×1056 源画布增加左右各 32、顶部 128 像素透明边距，输出 768×1184；锚点平移相同距离，人物没有缩放。侧视保持 512×768。每个完整 PNG 与最终包对应帧一致，左图是右图的精确镜像。GIF 使用应用现有半尺寸和固定底色；逐帧检查量化后像素、帧序、左右镜像和时长，不将 GIF 当作透明原稿。

服装先按原生归属重组，再按后发、脸部、前发重组。声明归属之外的 RGBA 与原片完全一致，原片不透明的前景手部保留；后发可以合理地出现在半透明抗锯齿轮廓后面，这部分按 destination-over 精确计算，不误称所有半透明前景 RGBA 不变。原版保留已有的窄幅头皮边缘遮盖区域，不扩大为任意身体覆盖权限。女版原版此前审阅的八处手形另作原片像素检查。

`mode: source` 的表情帧保留原片。原版柔和微笑仅处理现有嘴形，眨眼时并不保证整张脸完全不变；侧视男女各十个眨眼或不确定姿势使用原片整张脸部。不能把技术检查描述成新增了完整表情动画。

## 与 PR #58 相同帧的服装比较

审计将本轮实际导出的“仅衣服” CharacterPack 与 PR #58 已提交的实际包比较，排除新增头发／嘴形造成的无关像素差异。

- 男版原版、男版侧视、女版原版的衣服全帧保持不变。
- 女版侧视只有原生 ID 32 和 92 改变：分别 33、315 像素，范围限定在 `[292,581,300,590]` 与 `[253,382,270,405]`。它们对应原视频索引 58、240。其他 100 个姿势不变，上装全 102 帧不变。
- 这些裙料修补只用于新的 `complete-day`；旧 `tailored-day` 素材及哈希保留。

实际局部对比：[女版侧视裙料修补 2 倍图](review/female-side-cloth-repairs-2x.png)。图中同时显示原人物、PR #58 衣服、修补衣服和完整造型，不能仅凭完整造型把头发变化也算作裙料修复。

## 视觉检查与限制

技术通过只说明导出与素材归属符合约定，不等于所有画面已经达到最终美术标准。完整造型、同帧原片／仅衣服／完整造型比较、原生关键帧，以及头发／耳朵／肩颈的 2 倍细节都在 [review/](review/)；原始应用 GIF 单独保留。

已检查男女两视角原生关键帧、跑步同帧头部、跳跃肩颈局部及逐帧序列。新发型在这些姿势中有清晰发束体积，耳朵可以局部被覆盖，未见本轮新增的悬空耳片或额外肤色块。女版侧视 ID 32 的小块误露肤、ID 92 的裙内缺口在实际同帧导出中闭合；完整外观与仅衣服版本的修补区一致。

仍有需要明确保留的发型与衣料组合问题，不能用技术检查通过替代美术验收：

- **女版侧视跳跃原生 ID 77**：下巴后方、领口中央有一束看起来孤立的棕色发尾；仅衣服列没有，完整造型列可见。经逐层核对，它是旧 `hair-front` 的孤立片，棕片位置的后发实际透明；矩形 `headBounds` 把该段颈部／领口也包含在内，前景保护未阻止前发覆盖，所以这处并非合理的后发露出。该局部有 321 个可见变化像素；新素材与原有侧视波波头此帧的前后发 RGBA、遮罩、偏移和姿势元数据完全相同。本轮保留这个尚未修复的发层／头颈分区缺陷，未扩大或放松合成保护。见 [三列头发／领口 2 倍对照](review/female-side-jump-head-neck-2x.png)。因此耳缘连续不代表整个发型与领口都没有穿帮。
- **男版侧视下蹲／跳跃原生 ID 82**：领口与前肩／袖上缘存在角状切口，衣服还有明显拟合感；“仅衣服”和“完整造型”均有，本轮头发没有加重。见 [2 倍肩颈细节](review/male-side-jump-head-neck-2x.png) 和 [原片／衣服／完整造型原生局部](review/male-side-native82-source-clothes-look.png)。
- **女版侧视跳跃原生 ID 97**：前侧前臂有一处小暗色衣料碎片，原片没有，旧衣料已有，本轮外观未触及。见 [同帧三列对照](review/female-side-native97-source-clothes-look.png)。这说明已声明的衣料归属也需要继续人工审阅；像素保护检查无法自动断定每个声明像素在美术上都属于衣服。
- **女版原版跳跃原生 ID 90**：曾怀疑腋下露出背景是衣料缺口，三列对照确认原视频本来就有这处臂躯自然空隙，应保留，不列为本轮或衣料缺陷。见 [原片自然间隙对照](review/female-original-native90-source-clothes-look.png)。

因此本轮功能与可审阅交付通过，发型／基础表情接入以及限定两处裙料修补完成；美术验收仍有上述未解决项，不能宣称完整造型已经无穿帮。

已知限制：两个视角来自不同源视频，脸部朝向、光照、原片头形变化、动作节奏和相位不同；相近发型也分别绘制，发梢与光泽并非同一张图投影。除上面精确列出的发尾遮挡和两处旧衣料问题，原版男衬衫部分领口／袖折仍偏硬；女版部分跳跃外裙缘仍有台阶。原片模糊和抠图边缘保留，头发没有独立惯性模拟。侧视连续两跳仍是一次原片动作，不补造庆祝或新的动作周期。

## 复现与证据来源

```sh
CHROMIUM_PATH=/usr/bin/chromium npx playwright test tests/e2e/dual-view-complete-looks.spec.ts --workers=2
node scripts/verify-dual-looks-exports.mjs /tmp/dual-looks/male/exports.json
node scripts/verify-dual-looks-exports.mjs /tmp/dual-looks/female/exports.json
node scripts/build-dual-looks-review.mjs /tmp/dual-looks
```

`build-dual-looks-review.mjs` 仅对真实导出加标签、底色、裁切与整数倍局部放大，不生成衣服或头发。比较 GIF 共用展示调色板；跨视角图按两份原生时钟各自采样，显示三秒后停止，不伪造共同无缝循环。`comparison-provenance.json` 记录对应帧、原视频索引和文件 SHA；`actual-downloads.json` 记录最终下载；`checks/review-integrity.json` 独立解码检查全部 135 份 PNG、GIF 与 ZIP，其中 50 份 GIF 包括 36 份应用原始导出及 14 份比较图，另有四份最终 CharacterPack。

四份最终 CharacterPack 随证据提交。含重复原片的原生工程、配对工程和仅衣服控制包在浏览器测试中实际保存和重开，证据只记录它们的 SHA 与大小，避免再复制多份大原片 ZIP。

首次测试暴露的是验收脚本问题：故障路由未匹配 Vite 的 `?no-inline` 查询串；将 `scale` 对象误用身份比较；对大 ZIP 使用深对象比较耗尽 Node 堆；以及 Playwright 对原生禁用 `<option>` 的通用 matcher 判断不符。最终脚本改为路径匹配并确认拦截次数、元数据深值比较、`Buffer.equals` 字节比较及原生 `disabled` 属性检查。修正这些检查未改变被冻结的运行代码或美术素材；中断及重跑不计为新增用例。
