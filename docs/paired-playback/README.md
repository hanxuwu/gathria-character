# 双视角工作台：循环播放与后台恢复

工作台原先每次显示动作帧，都重新合成人物、服装和头发，再复制整张像素图。跑步重复到同一帧时也会重复这项工作。现在按当前渲染器与原生帧 ID 缓存显示画布，命中后直接绘制；人物素材、24 FPS 动作时钟、跳跃接点与导出路径保持原样。

缓存有帧数和像素两道上限：96 帧、48 Mi 像素，约 192 MiB 原生 RGBA 存储。这个数字不代表浏览器总内存或 GPU 占用。首次遇到新帧仍要合成，超大帧只绘制一次并释放。成功换装、重开或切换人物后会清理旧缓存；失败操作保留当前搭配。

同时修复后台时钟：页面隐藏时，即使浏览器没有再调用一次 RAF，也会清除计时基准。切回来后从原来的腾空或落地姿势继续，保留落地后接跑步的意图。

## 看播放差异

- [男版慢设备模拟：修改前／后](review/male-original-cpu4-trace-before-after.gif)
- [女版慢设备模拟：修改前／后](review/female-original-cpu4-trace-before-after.gif)

**这两张是浏览器观察轨迹的诊断回放，不是录屏或应用导出 GIF。** 在同一 Chromium 环境施加 4 倍 CPU 限速，记录实际画布的姿势 ID 与观察时间，再用同一组原生图像重放。左边修改前、右边修改后，使用同一开始姿势、固定裁剪和缩放；共同的 20ms 展示网格带来小于 20ms 的时间量化，结尾暂停仅用于审阅。完整来源与时间记录见 [trace-provenance.json](review/trace-provenance.json)。

每个场景预热超过两个原生跑步周期，再观察约 3 秒。单视角慢设备模拟结果：

| 场景       | 修改前观察到的姿势变化 | 修改后观察到的姿势变化 |
| ---------- | ---------------------: | ---------------------: |
| 男版原视角 |                     24 |                     45 |
| 男版侧视   |                     34 |                     49 |
| 女版原视角 |                     24 |                     55 |
| 女版侧视   |                     35 |                     59 |

12 个预热场景中，新版测量窗口的重复合成调用均为 0。正常速度的单视角窗口观察到约 72 次姿势变化，与原生 24 FPS 相符。这里统计的是绘制后观察到的姿势变化，观察器可能合并回调；它不是精确渲染 FPS，也不是实际手机测试或帧率保证。并排模式的计数合计两张画布，不能当作单个人物 FPS。

## 功能与视觉验收

功能检查、实际导出一致性与生产页面结果记录在 [verification.md](verification.md)。性能测量与后台恢复的受控时钟测试分开记录；后者只验证状态和像素保持，不测量真实设备帧率。

本轮改善循环播放负担和后台恢复。首次播放尚未缓存的新动作仍需计算；源视频中跑跳接点的头部俯仰、双脚落地转单脚支撑的造型差异依然存在。此改动没有补画新的动作过渡，也没有改变基础 Jump 或跑跳 GIF 的内容。

实际应用导出继续从[侧视跑跳审阅](../kling-takeoff-refine/README.md#查看实际效果)和[原视角落地审阅](../kling-landing-run/README.md#审阅材料)查看。
