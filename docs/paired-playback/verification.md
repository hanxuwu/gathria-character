## 性能测量的范围

[测量脚本](../../scripts/measure-paired-playback.mjs)只在开发服务器的模块响应中记录合成函数调用，在浏览器中观察实际画布的动作帧 ID；不改变人物像素或动作时钟。每个性别各测原视角、侧视和并排模式，分别使用正常 CPU 与 4 倍 CPU 限速；每个窗口约 3 秒，先预热超过两个跑步周期。

基线和修改后的测量使用相同机器、浏览器、原生帧和搭配。记录转换后的工作台模块哈希，以区分两次运行。观察计数、CPU 计时与机器负载相关，只作为本次诊断结果；不是统计意义上的跨设备基准。缓存命中后的合成调用为 0，不代表首次加载或新动作的合成成本消失。

诊断 GIF 根据这些观察轨迹重建，保留漏掉原生帧后的姿势跳变和观察间隔；不插值、不补帧。为了避免部分 GIF 播放器把 10ms 帧拉长，展示采用共同 20ms 网格；原始时间戳另存。两边从共同姿势开始，取完整的 2 秒共同观察窗口，结尾暂停与重播均有标签。

## 视觉检查与限制

普通速度维持原来的动作节奏；慢设备模拟中，暖缓存循环能显示更多连续姿势。画面来自同一组已经审阅的原生图像，脸型、身体比例、发型和衣服没有重画。

原素材的头部俯仰、落地支撑变化、模糊和衣料轮廓问题仍存在。后台恢复前后的像素一致和功能测试通过，不能替代这些动作接缝的美术验收。

## 远端测试竞态修订

基线的 PR CI 有 174 项浏览器测试全部通过；相同提交的 Push CI 为 173 项通过、1 项失败。失败场景在等待腾空姿势后，经过多次 Playwright 往返才点击 Run，慢速执行时已经落地，导致瞬时 `Jump` 断言失效。

修订后的测试先安装一次性浏览器观察器，在实际画布出现规定腾空姿势时直接点击已有 Run／Idle 按钮，记录输入时的姿势。仍要求真实画布显示 `Jump + pending`，并保留落地帧和动作阶段断言；没有放宽运行时规则或删掉缓冲检查。对应运行日志和诊断保留在 `checks/`。
