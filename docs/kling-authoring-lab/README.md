# Kling 服装制作与组合检查

本批先按用户要求合并了 PR #45 与 #46，再从 main
`5bb6966d247ece4c0d8a33f083a44208b12148ab` 建立独立开发分支。
新增两个浏览器本地工具，继续使用已认可的 Kling 男女原人物、注册锚点与动作。
没有重新生成角色、改变默认衣物或修改既有素材库。

## 在哪里打开

打开 `/workbench.html?character=male&mode=wardrobe`，女版使用 `character=female`。
页面顶部的 **Make and review** 提供两个按钮：

- **Create clothing**：制作覆盖完整姿势库的服装材质配色版本。
- **Check combinations**：批量检查指定的服装、发型、表情与发色组合。

它们都在现有换装页面内，不增加新的主页面。进入工具时主预览暂停；关闭、取消
或导入失败不会替换当前搭配。只有明确应用候选或组合才修改主工作台，可以撤销。

## 服装制作向导

1. 穿上要作为模板的上衣、裤子或裙装，点击 **Create clothing**。
2. 选择模板，填写新 ID 与名称。在原生画面上取衣料颜色，或输入原生坐标取色。
   设置目标颜色与匹配范围。可导入本地参考 PNG，从图中取色并保存来源。
3. 构建全部已注册姿势。处理只作用于模板已拥有的不透明 RGB 像素，保留轮廓、
   透明度、归属遮罩、锚点、光影纹理和原动作时序。共享图集像素只处理一次。
4. 查看覆盖动作与几何极值的困难姿势，比较原服装/新服装，可显示锚点。
   每个姿势分别接受、拒绝或保持待审；改动设计后，旧审核决定失效。
5. 保存制作草稿，或在完成困难姿势审核后进入完整候选窗口。继续检查动作、朝向、
   发型及其他服装，下载 **Save created clothing** 和 **Save clothing creation report**，
   最后明确应用。主工作台的保存重开、混搭与 CharacterPack 导出继续使用。

制作草稿 ZIP 包含精确版本的模板衣物、参数与可选参考 PNG。重开时重新构建并
核对输出哈希，之后才恢复审核决定。同一源人物与注册下，可以从不同当前搭配
恢复草稿；损坏的模板、参考或审核绑定会被拒绝，原会话保留。

**范围说明：**这是完整姿势库的材质配色制作流程。新袖长、裙形、装饰和遮挡结构
仍需要绘制对应素材。参考 PNG 用于取色与设计对照，不会被自动贴到全部姿势上。
局部图案补绘使用已有 painting kit；衣料归属和接缝使用已合并的 mask workbench。
参考图目前要求非交错、8-bit RGBA PNG，最大 8 MiB、4096 像素边长与 4 百万像素。

## 组合视觉检查台

1. 点击 **Check combinations**，明确添加本轮需要的衣物。加载只进入检查会话，
   不改变正在穿的衣服；最多 16 件，包含打开时已有的衣物，不自动删除自定义素材。
2. 选择服装搭配、发型、表情、发色、动作和朝向。发型与表情使用当前已验证的
   外观素材库；要检查另一素材库，先在主工作台选择相应发型后重新打开检查。
3. **Plan combinations** 展示总组合数、计划组合数、采样位置与因素配对覆盖。
   小范围可穷举所选组合；大范围可使用确定性的代表组合选择。超限穷举会明确拒绝。
4. **Scan planned combinations** 顺序渲染并比较真实像素和相邻时刻变化。
   可以取消，已完成的行保留。失败渲染单独记录，不能标记为已视觉检查。
5. 点击某行，查看同帧对比、叠加、局部和连续播放。为具体行记录待审、问题或
   已检查及备注。选择最多 24 个成功样本，导出带 PNG 与哈希记录的对照图 ZIP。
   JSON 报告可以保存和重开；重新导入的测量值明确标为未重新验证，需重新扫描核实。
6. **Use this combination and review** 才把该搭配应用到原工作台，并带入相同发型、
   表情的服装参考及选定帧，继续使用已有的细节审阅工具。

比较两边始终使用相同外观配置，服装参考可以是打开检查台时的搭配或原始服装。
因此发型或表情本身的正常变化不会混入该行的服装差异值。衣物修复前后的比较
仍需要指定实际原衣物作为参考；“与原人物衣物不同”不等于穿帮。

**覆盖说明：**一批最多 24 个组合、600 个样本，并受原生像素工作量限制。
“穷举组合”指本次选定的搭配组合，不代表动画每一帧都被采样。报告列出未采样
时间轴位置、重复停顿帧和遗漏的因素配对。相邻运动检查使用真实下一时间点；
单次动作末尾不会伪造首尾连接。完成采样不等于动作已经获得视觉验收。

当前不把独立绘制的主题人物作为换装因素；这些主题有自己的画面与时序。
检查台也不推断皮肤语义，不把变化像素数当作美术质量分数。

## 实现与兼容

- `garment-authoring.ts`：规范化源文件，版本化材质算法、真实合成预览、完整姿势库
  生成、困难姿势计划、输出绑定审核和便携制作草稿。
- `ClothingCreationWizard.tsx`：四步制作、参考图取色、原生定位、取消及恢复。
- `combination-review.ts`：精确素材绑定、组合与位置覆盖、实际渲染扫描、部分结果
  保留和严格报告解析。先验证文件与描述，再按实际选中素材解码，避免无用的大图解码。
- `CombinationReviewWorkbench.tsx`：因素选择、检查队列、同帧/连续预览、人工记录、
  报告重开、真实渲染对照图和明确应用。
- `WardrobeEditor.tsx` / `GarmentCandidatePreview.tsx`：入口、候选隔离、版本保存、
  撤销及相同外观参考交接。

服装继续使用已有 V1/V2/V3 格式。V2 手部修正、V3 固定领口审核信息均保留。
没有改变 WardrobeProject 或 CharacterPack 格式；运行时仍然本地、确定性处理，
不调用绘图 API、不上传参考图。旧搭配及旧导出保持原规则。
