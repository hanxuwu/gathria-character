# 跑步接跳跃：先收步，再蓄力

侧视男女角色现在有三处按步态匹配的起跳入口。接到跳跃请求后，用原视频已有的 1–4 帧收步、前倾画面进入基础 Jump，减少从跑步直接切到下蹲的突变。

| 对比项                     | 上一版 V3  | 本轮 V4              |
| -------------------------- | ---------- | -------------------- |
| 每个跑步周期的起跳入口     | 2 处       | 3 处，相隔 6 tick    |
| 最长排队到开始过渡         | 约 458ms   | 约 250ms             |
| 最长到基础 Jump 的蓄力起点 | 约 458ms   | 约 417ms，已包含过渡 |
| 原地单跳                   | 完整 28 帧 | 同样的 28 帧         |

这些是 24 FPS 控制器时钟的上限，不包含设备绘制延迟。开始过渡不等于已经离地；主跳跃仍保留完整蓄力。原视角、走路起跳、落地接跑步、图集、服装、脸型和比例保持原样。

## 在页面中试用

1. 打开 `/workbench.html?mode=paired&character=male`，女版将参数改为 `female`。
2. 应用完整日常造型，选择侧视、单次跳跃，开始跑步，再点击“跳一次”。
3. 在不同迈步位置重复试用。角色先做起跳准备，然后完整跳一次并继续跑步；准备和腾空中再次按跳跃不会追加一次跳跃。
4. 在准备阶段暂停并保存双视角项目，重新打开应保留该过渡帧及落地意图。拖动基础动作帧滑条会退出这段准备，明确选择基础 Jump 的帧。

## 兼容与边界

- 新侧视配置为 `single-jump-v4`。原视角仍用 V2；历史 V1、V2、V3 CharacterPack 保留原路线。
- 运行时、独立播放器和跑跳 GIF 使用同一套过渡逻辑。单独导出 Jump 不包含跑步收步段。
- 双视角项目只在保存起跳准备状态时增加已校验的 checkpoint。普通历史项目仍可打开；包含新 checkpoint 的文件不保证旧版应用可读。单视角原生项目继续只保存搭配、动作和朝向。
- 没有宣称完全无穿帮：原视频在不同动作间的头部俯仰、脸部阴影和既有衣料轮廓仍有差异。女版靠近蓄力时仍能看到少量头发轮廓变化。

[功能与视觉验收](verification.md)分别记录检查结果。[选帧记录](selection.md)解释为何排除男版头发下沉帧，以及为何最后一处入口只接一帧。
