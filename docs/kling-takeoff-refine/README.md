# 侧视跑跳：减少起跳等待

在上一轮落地接跑步修订的基础上，本轮给侧视男女各增加一个经过姿势检查的起跳接点。原先每个跑步周期只有一个接点，刚错过时要再等近一圈；现在手臂回到腰侧、支撑脚合适的另一处也能进入跳跃蓄力。

| 行为                     | 此前                           | 本轮        |
| ------------------------ | ------------------------------ | ----------- |
| 侧视跑步起跳接点         | 每周期 1 处                    | 每周期 2 处 |
| 侧视控制器最长排队等待   | 近 750ms                       | 近 458ms    |
| 原视角控制器最长排队等待 | 近 333ms                       | 保持原样    |
| 基础跳跃、落地接跑步     | 单次完整跳跃；移动时提前接跑步 | 保持上一版  |

这些时长是原生 24 FPS 动作时钟的等待上限，不包含浏览器绘制或设备调度延迟。改动没有加速动作、跳过蓄力或重绘人物。

## 查看实际效果

运行 `npm run dev`，打开 `/workbench.html?mode=paired&character=male`（或 `female`），选择 **侧视**、**单次跳跃**。点击 **跑步** 后，在不同步态按 **跳一次**；仍只完成一次跳跃，再继续跑步。

## 本轮选择和边界

男版新增原生帧 47 后起跳，女版新增原生帧 39 后起跳。原接点仍保留，起跳始终从基础 Jump 第 0 帧开始，完整播放蓄力和腾空。[选帧证据](selection.md)包含原素材与换装结果对比，以及未采用的候选姿势。

我们还测试了删去侧视落地恢复的两帧，可以省约 83ms，但手臂和头部转动变得更集中，仍不能解决双脚落地转单脚支撑的姿势差异，因此没有采用。原视角剩下的恢复帧也有必要保留。本轮改善起跳响应，保持已经审阅的落地出口。

原视频在进入跳跃时仍有头部俯仰、身体前倾与支撑姿势变化。彻底消除这些差异需要匹配动作的过渡画面，不能以缩短等待或测试通过代替美术验收。

## 兼容与验收

- 侧视的新动作配置 ID 为 `single-jump-v3`，原视角仍使用 V2；数据结构版本没有改变。
- 已导出的精确 V1／V2 CharacterPack 仍使用原来的起跳和落地接点。
- 图集、服装、脸型、比例、锚点、动作帧序和 24 FPS 未改变；基础 Jump GIF 保持一致。
- [功能与视觉验收](verification.md)分别记录实际操作、独立播放器、导出像素和剩余视觉限制。
