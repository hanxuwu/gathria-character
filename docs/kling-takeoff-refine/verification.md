# 起跳响应：功能与视觉验收

本轮只增加侧视跑步起跳的第二个接点。原视角、跳跃内容、落地出口及所有图像保持上一轮版本。

## 功能检查

- **656 项单元测试／67 个文件通过。** 新测试覆盖男女各 72 个跑步时刻（每个帧位含整帧及小数时刻），检查接点选择、时间余量、完整蓄力、重复输入和历史 V2 的原始等待行为。
- **2 项实际浏览器场景通过，耗时 2.8 分钟。** 每个性别检查新增接点、原接点和跨周期接点，均按一次跳一次并接回跑步。
- **2 个 CharacterPack、8 个实际 GIF／394 个解码帧通过独立校验。** 209 个侧视原生帧的图集 PNG 字节、尺寸、矩形、锚点和动作帧序未改变。4 个单独 Jump GIF 与上一版逐字节一致；左右衔接 GIF 为完整镜像。
- **4 次全新独立播放器导入通过。** 当前侧视 V3 和根据已提交实际 JSON 重建的历史 V2 均保留各自配置；当前包重新导出与输入逐字节一致。
- TypeScript 与 Vite 生产构建通过。生产页面的男女 × 两视角、动作返回和桌面／390px 移动对比检查通过，没有页面错误、HTTP 错误或横向溢出。原视角的两份当前配置与上一版完全一致；旧 V1／V2 仍通过精确配置识别，不以名字相似推断兼容。

[核心测试](../../src/core/takeoff-motion.test.ts)检查所有输入相位；[浏览器测试](../../tests/e2e/takeoff-refine.spec.ts)操作实际按钮并记录时间；[独立校验脚本](../../scripts/verify-single-jump-exports.mjs)不导入运行时控制器或合成器，按审阅接点重新推导帧序和像素。

## 等待时间的含义

18 帧、24 FPS 的侧视跑步原先每圈只有一个接点，最长排队等待接近 750ms。新增接点将两段间隔分为 7 帧和 11 帧，最长等待接近 458.33ms。这个上限属于控制器动作时钟，不是所有设备的端到端响应保证。

本次浏览器测得的请求到首次显示 Jump 的时间如下，含首帧绘制与调度开销：

| 人物 | 新增接点：原生／实测 | 原接点：原生／实测 | 跨周期：原生／实测 |
| ---- | -------------------- | ------------------ | ------------------ |
| 男版 | 375／410.6ms         | 250／280.2ms       | 416.7／463.8ms     |
| 女版 | 250／278.3ms         | 250／279.4ms       | 416.7／444.5ms     |

实际导出示例在完整跑步一圈之后请求跳跃：男版进入 Jump 的 GIF 时刻由 1420ms 提前到 1130ms，女版由 1290ms 提前到 1000ms。两例各提前约 290ms，且完整落地部分不变。男版新流程 72 帧／3000ms，女版 69 帧／2880ms。GIF 采用累计百分之一秒舍入；CharacterPack 仍为精确 24 FPS。

## 视觉检查

手臂已回到腰侧的新接点比提前半圈、手臂还在胸前的候选更合适。另一个较晚候选已经抬起前膝，切入跳跃的落脚姿势也更生硬，因此没有采用。实际换装导出的关键帧与原素材一起核查，参见[接点选帧](selection.md)。

新接点改善响应，不代表消除了进入跳跃时的头部俯仰和身体前倾。落地双脚支撑转跑步单脚支撑的差异仍存在。另行试验删去两帧恢复姿势仅缩短了时间，并未明显改善这些差异，因此保持原有落地配置。

所有图像未改动，本轮单帧的脸型、比例、衣服轮廓保持一致；原素材已有的模糊及衣料边缘问题也没有被本轮修复。

## 历史原片回归

上一版远端 CI 的 8 个失败场景仍以默认模式验证原片的 50 帧 Jump、旧工程 V1 或旧包哈希，但应用默认已切为单次跳跃。这些旧用例现在明确选择 **原片对照**，保留全部原有帧数、图像、文件哈希与重开断言；单跳和新接点由独立场景验证。

**8 项旧场景本地重跑全部通过，耗时 16.6m。** 加上本轮 2 项起跳场景，共执行 10 项实际浏览器测试。此前 8 项失败的原片回归均已覆盖；本轮没有声称在本地重跑完整远端浏览器套件。

[检查收据](checks/README.md)包含本轮日志、独立导出报告、历史回归结果与生产页面检查结果。之前远端失败日志保留为诊断证据，不作为新版本通过的证明；新提交的完整远端 CI 结果需独立查看。
